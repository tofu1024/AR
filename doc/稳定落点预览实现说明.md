# 稳定落点预览实现说明

实现版本：1.2.1（versionCode 4）。日期：2026-10-26。

## 1. 操作方式

1. 初始瞄准点为屏幕中心的十字光标，移动手机可以改变瞄准方向。
2. 也可以点击 AR 画面选择新的屏幕瞄准点；点击表单和按钮不会选择 AR 目标。
3. 找到有效平面后显示黄色预览，保持瞄准稳定，满足时间窗口条件后变绿。
4. 按 Place marker 确认，成功创建 Anchor 后显示橙色立方体。
5. 填写问题并 Submit issue。重新按 Place marker 可替换原标记；新锚点创建失败时保留原标记。

绿色平面边界代表 SDK 正在跟踪该平面；绿色落点光标代表当前候选位置通过了本项目的稳定性检查，两者含义不同。

## 2. 算法与默认参数

PlacementStability 维护同一 trackableId 的滑动时间窗口：

| 条件 | 默认值或处理 |
| --- | --- |
| 连续观察时长 | 约 0.4 秒 |
| 最少样本 | 6 个不同时间的有效命中 |
| 位置波动 | 所有窗口样本距均值不超过 2.5 厘米 |
| 法线波动 | 所有样本法线与平均法线夹角不超过 5° |
| 新鲜程度 | 确认时最近样本不超过 0.15 秒 |
| 采样中断 | 间隔超过 0.2 秒时重新收集 |
| 大幅移动 | 相邻落点跳动超过 6 厘米或法线变化超过 12°时重新收集 |
| 平面切换、命中丢失、跟踪受限、应用暂停 | 重置窗口，不能直接沿用绿色状态 |

ARPlacement 同时检查整体 AR 会话和单个平面的 Tracking 状态，排除已合并的旧平面。射线仍采用 PlaneWithinPolygon，只接受识别范围内的实际命中。

屏幕预览采用帧率无关的指数平滑：alpha = 1 - exp(-12 * deltaTime)，位置用 Lerp，旋转用 Slerp。切换平面时直接初始化新预览，避免从上一平面拖尾过去。

这些阈值是本项目的可调启发式参数，不是 ARCore 的精度或置信度承诺。低帧率、较大拍摄距离或手抖可能使确认更难，应在同设备同场景下比较后调参。

## 3. 确认和坐标

确认按钮只在候选有效且稳定时可用。点击后再次进行真实射线检测，并重新校验稳定性；不会将平滑后的预览坐标直接写入后端。

优先将 Anchor 附着到命中的平面；平台不支持或附着失败时尝试 TryAddAnchorAsync。锚点创建成功后再替换旧标记，标记作为 Anchor 的子对象，沿表面法线朝相机侧偏移 4 厘米。

上报位置取当前锚点原点，对应表面命中位置，不是立方体偏移后的中心。锚点跟踪受限时禁用提交；恢复 Tracking 后可以继续。旧锚点在替换、提交成功或场景销毁时清理；异步创建过程中若应用暂停或请求失效，会清理迟到的锚点结果。

## 4. 代码位置

- Assets/Scripts/PlacementStability.cs：时间窗口和一致性检查。
- Assets/Scripts/ARPlacement.cs：有效平面筛选、选点、预览、确认、Anchor 生命周期及提交坐标。
- Assets/Scripts/PlaneOutline.cs：只显示正在跟踪的未合并平面，边界线宽改为 4 毫米。
- Assets/Scripts/IssueForm.cs：瞄准十字、Place marker 和 Submit issue 的可用状态。
- Assets/Editor/InspectionStabilityChecks.cs：构建前运行的确定性检查。

## 5. 验证与限制

构建前 11 项检查通过，包括静止小幅抖动、过期样本、切换平面、移动瞄准、法线变化、样本不足、完整窗口、同帧大幅跳变、无效数值、墙面姿态及清空状态。

Unity 实际 C# 编译、IL2CPP/Gradle 构建及 APK 签名校验通过，1.2.1 已覆盖安装到手机并启动。首次真机检查发现圆柱预览依赖的 CapsuleCollider 被裁剪，改用已经验证过的扁平立方体预览后重新构建安装；没有保留带该错误的包作为最终版本。

用户已在真机确认“光标变绿并成功放置”。仍未量化放置误差或漂移改善，也未将此结果当作所有墙面、跟踪丢失恢复、UI 拦截及问题上报均已验收。

本次实现不改变 ARCore 的平面拟合算法，也未启用 Depth。绿色边界可能继续随 SDK 环境估计变化，稳定光标和 Anchor 不等价于精确物体轮廓或厘米级定位。
