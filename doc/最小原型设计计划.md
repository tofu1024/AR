# 现场巡检问题标注：最小原型设计计划

## 1. 目标与范围

依据面试题要求，实现以下最小闭环：

```text
Unity 真机识别水平面并放置标记
  → 填写问题并提交
  → Go 保存到 SQLite
  → React 刷新查看问题
  → React 修改处理状态
  → Go 重启后数据仍然存在
```

工程保持为一个 Unity 场景、一个 React 页面、一个 Go 服务和一个 SQLite 文件。优先完成必做功能、异常提示和真机验证，不追求复杂架构和精美界面。

本文是实施计划，尚不代表相关功能已经开发或验证。

## 2. 技术方案

| 部分 | 方案 | 理由 |
| --- | --- | --- |
| 手机端 | Unity LTS、C#、AR Foundation、ARCore XR Plugin | 使用成熟的官方 AR 能力，优先适配 Android 真机 |
| 管理端 | React、TypeScript、Vite | 单页面实现，依赖少、启动方便 |
| 后端 | Go 标准库 net/http、database/sql | 只有四个接口，无需额外 Web 框架 |
| 持久化 | SQLite、modernc.org/sqlite 驱动 | 单文件存储，无需安装数据库服务及 C 编译环境 |
| 界面 | Unity UGUI、React 普通 CSS | 满足表单、列表和提示即可 |

实施前确认存在支持 ARCore 的 Android 手机。Unity 使用正式 LTS，AR Foundation 与 ARCore 插件选择编辑器支持的兼容正式版本；最终将实际版本记录在 README 并提交依赖锁定文件。

不引入 ORM、复杂分层、全局状态管理、微服务或额外部署平台。

## 3. Unity 手机端

### 3.1 场景组成

- AR Session、XR Origin 和 AR 相机。
- ARPlaneManager：检测水平平面；根据 2026-10-26 补充需求，同时开启竖直平面以支持墙面标注。
- ARRaycastManager：将屏幕触摸转换为平面命中点。
- 简单立方体标记。
- 表单：标题、描述、优先级、提交按钮和提示文字。
- 可配置的 Go 后端地址。

### 3.2 操作流程

1. 进入场景，提示用户缓慢移动手机以扫描水平面。
2. 点击检测到的平面，放置一个待提交标记。
3. 再次点击平面时，移动当前待提交标记。
4. 填写标题、可选描述和优先级。
5. 使用 UnityWebRequest 提交 JSON。
6. 成功后提示用户，清空表单并移除待提交标记，进入下一条录入。
7. 失败时保留标记和输入内容，允许重试。

每次只维护一个待提交标记，不实现历史问题恢复。

### 3.3 交互约束

| 情况 | 行为 |
| --- | --- |
| 尚未检测到平面 | 显示扫描引导 |
| 触摸未命中平面 | 不放置标记 |
| 点击输入框、按钮或表单面板 | 拦截触摸，不执行 AR 放置 |
| 未放置标记 | 阻止提交并提示 |
| 标题去除首尾空白后为空 | 阻止提交并提示 |
| 请求发送中 | 禁用提交按钮，避免连续点击 |
| 请求成功 | 明确提示成功并重置录入状态 |
| 超时、连接失败或服务端报错 | 明确提示原因，保留录入内容 |

位置使用命中点的 Unity 世界坐标，单位为米，只表示当前 AR 会话内的位置。不承诺跨会话、跨设备恢复真实物理位置。

### 3.4 脚本职责

- AR 放置脚本：平面命中、UI 触摸拦截、创建和移动标记。
- 表单脚本：输入校验、提交状态、成功和失败提示。
- API 客户端：地址配置、JSON 请求、超时和错误处理。
- 数据模型：与 Go、React 保持一致的字段名称。

## 4. Go 后端

### 4.1 接口

| 方法 | 路径 | 用途 | 成功响应 |
| --- | --- | --- | --- |
| GET | /api/health | 服务运行状态检查 | 200 |
| POST | /api/issues | 创建问题 | 201，完整问题对象 |
| GET | /api/issues | 查询问题列表，按创建时间倒序 | 200，items 数组 |
| PATCH | /api/issues/{id}/status | 修改状态 | 200，更新后的完整问题对象 |

健康检查响应：

```json
{"status":"ok"}
```

创建请求：

```json
{
  "title": "入口墙面破损",
  "description": "左侧墙体存在裂缝",
  "priority": "high",
  "position": {"x": 0.42, "y": 0.03, "z": 1.26}
}
```

后端生成唯一 ID、createdAt、updatedAt，并将初始状态固定为 open。时间采用 UTC RFC 3339 格式。

完整问题结构：

```json
{
  "id": "由后端生成",
  "title": "入口墙面破损",
  "description": "左侧墙体存在裂缝",
  "priority": "high",
  "status": "open",
  "position": {"x": 0.42, "y": 0.03, "z": 1.26},
  "createdAt": "由后端生成",
  "updatedAt": "由后端生成"
}
```

列表响应使用包装对象，空列表返回空数组：

```json
{"items":[]}
```

状态更新请求：

```json
{"status":"in_progress"}
```

统一错误响应：

```json
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "标题不能为空"
  }
}
```

### 4.2 校验和错误处理

- 标题去除首尾空白后不能为空。
- priority 只能为 low、medium、high。
- status 只能为 open、in_progress、resolved；三种状态允许直接切换。
- position 必须提供合法的 x、y、z 数值；零是合法坐标，不能用零判断字段是否缺失。
- JSON 格式错误、缺少必填字段或枚举非法返回 400。
- ID 不存在返回 404。
- 数据库保存失败返回 500，详细原因写入后端日志。
- 只有数据库写入成功才向客户端返回成功。

### 4.3 持久化

只创建一张 issues 表：

| 字段 | 用途 |
| --- | --- |
| id | 主键，后端生成的唯一字符串 |
| title | 标题 |
| description | 描述，缺省为空字符串 |
| priority | 优先级 |
| status | 状态 |
| position_x、position_y、position_z | 三个坐标数值 |
| created_at、updated_at | 创建和更新时间 |

直接使用参数化 SQL，不引入 ORM。启动时执行 CREATE TABLE IF NOT EXISTS。数据库路径明确配置并固定解析，避免换目录启动时创建另一份数据库；启动日志输出实际数据库路径。

## 5. React 管理端

实现一个页面，顶部包含页面标题、刷新按钮和错误提示，下方展示问题表格。

表格字段：标题、描述、优先级、状态、位置、创建时间、操作。

- 页面打开时自动获取列表。
- 点击刷新按钮重新获取。
- 每行使用状态下拉框和保存按钮。
- 保存期间禁用该行保存操作。
- 保存成功后使用后端返回对象更新该行。
- 保存失败时显示错误，保留列表，明确区分待选状态与已保存状态。
- 显示加载中、暂无问题、请求失败等状态。
- 后端不可用时显示错误和重试入口，不能白屏。

使用 useState、useEffect、原生 fetch 和普通 CSS，不引入路由、全局状态库、组件库和自动轮询。

## 6. 局域网联通

```text
Android Unity → http://电脑局域网IP:8080
电脑 React    → http://localhost:8080
                         ↓
                   同一个 Go 服务
                         ↓
                   同一个 SQLite 文件
```

- 手机和电脑连接同一个可互通的局域网。
- Go 监听 0.0.0.0:8080。
- Unity 地址不能填写 localhost，应填写电脑局域网 IP。
- React 开发服务固定端口，例如 5173。
- Go 为实际 React 开发来源配置 CORS，允许 GET、POST、PATCH、OPTIONS 和 Content-Type 请求头。
- Android 演示构建允许 HTTP 请求，并配置相机权限。
- Windows 防火墙允许局域网访问 Go 端口。
- 先使用手机浏览器访问 /api/health，确认网络连通，再排查 Unity 请求。

## 8. 实施顺序与验收

| 阶段 | 工作 | 验收标准 |
| --- | --- | --- |
| 1 | 真机 AR 可行性验证 | Android 真机检测水平面并放置立方体 |
| 2 | Go 接口和 SQLite | 创建、列表、状态修改均可用，重启后数据保留 |
| 3 | React 页面 | 能查看真实数据、修改状态，断网有错误提示 |
| 4 | Unity 表单和请求 | 手机提交后，React 刷新能看到同一问题 |
| 5 | 异常及完整回归 | UI 不误放置，参数错误明确，失败保留输入 |
| 6 | 文档、录屏、交付 | 完整源码、README、AI_LOG 和两段视频齐全 |

先验证真机 AR，尽早暴露设备兼容、权限和构建环境问题。

### 8.1 最小验证清单

- 真机成功检测水平面，标记位于平面命中点。
- 点击按钮、输入框和表单面板不放置或移动标记。
- 未放置标记、标题为空时禁止提交。
- 连续点击提交不会在同一请求期间重复发送。
- 手机创建问题后，React 刷新可见，字段一致。
- 三种优先级和三种状态均可正常使用。
- 非法枚举、错误 JSON 和不存在的 ID 返回预期错误。
- 停止 Go 后，Unity 和 React 都显示明确错误。
- 更新状态后重启 Go，原问题和最新状态仍在。
- 使用相同数据库重新启动，不误切换为空数据库。

后端对关键校验、状态更新和数据库重新打开后的持久化编写少量测试。AR 识别、触摸拦截和手机网络请求必须真机验证。
