# 深度落点标注实现说明

版本：1.3（versionCode 5）。日期：2026-10-27。

## 1. 本次实现的目标

保留原有水平/竖直平面流程，增加独立 Depth 命中来源。当前瞄准点没有 ARPlane 命中时，只要有有效、新鲜且通过稳定性检查的深度落点，也可以确认标记。

本次增加的是可标注位置来源，不重建整面墙，不扩大或伪造 ARPlane 绿色边界。

## 2. 路由规则

| 平面命中 | 有效深度命中 | 行为及界面提示 |
| --- | --- | --- |
| 有 | 无 | 使用原平面流程，显示 Plane only 和深度回退状态 |
| 无 | 有 | 显示 Depth surface (no plane)，稳定后可放置 |
| 有 | 有，位置和法线基本一致 | 使用真实平面命中，显示 Plane + depth checked |
| 有 | 有，但明显冲突 | 清除候选稳定窗口，提示 Plane/depth disagree，保留之前已确认的标记 |
| 无 | 无 | 不生成候选，提示继续扫描 |

Depth surface (no plane) 指当前屏幕瞄准点没有有效平面命中，不代表场景中不存在其他 ARPlane。

两类命中由 ARRaycastManager 在同一屏幕位置、同一 Unity 帧内分别查询。只使用 PlaneWithinPolygon 和 Depth，不使用估计距离的 Instant Placement，也不随意退回特征点制造落点。

## 3. 深度开启、能力和新鲜度

- AR Camera 增加 AROcclusionManager，请求 Fastest 环境深度和时间平滑。
- 深度仅用于几何命中；设置 NoOcclusion，不在本轮改变标记的遮挡渲染。
- ARCore 项目设置明确配置 Depth Optional，未将深度能力列为安装必需条件。
- 检查实际 occlusion descriptor 的支持状态和当前环境深度模式。
- 每约 0.1 秒获取并立即释放一个环境深度 CPU 图像句柄，用于检查图像尺寸和时间戳，不进行自写像素到世界坐标转换。
- 至少观察到两张时间戳前进的图像才进入 Depth ready。重复获取同一张图像不会延长其有效期。
- 深度时间戳在相机时间戳可用时须相差不超过 0.5 秒；最近推进的深度图像最多保留 0.5 秒的新鲜度。
- 暂停、会话失去跟踪、图像时间倒退或长时间中断会使此前新鲜度失效。

状态区分 Depth checking、Depth unsupported、Depth waiting/stale 和 Depth ready。深度未就绪时保留平面流程，并明确显示 plane fallback。

Depth ready 表示当前深度数据流可用，不代表瞄准点必有深度命中，更不代表该处已经达到稳定或指定精度。

## 4. 落点有效性和一致性

深度落点须为有限数值、有效旋转，且距相机约 0.2～5 米。世界姿态和表面方向由 SDK 的 Depth Raycast 提供，不把深度图的相机 Z 值直接当作射线长度。

两类结果都有时，在同一个 Unity 世界坐标系比较：

- 距离差容许值为 min(15 厘米, 5 厘米 + 2% 拍摄距离)。
- 法线夹角不超过 30°，允许正反法线表示同一几何平面。
- 通过时保留原始平面命中点，不对两个结果直接取平均。
- 冲突时不自动认定其中一种一定正确，而是拒绝该候选并提示换角度或避开遮挡。

以上范围和阈值属于可调工程规则，不是 SDK 置信度或绝对精度保证。本次未自行接入 Raw Depth 置信度图或局部点云拟合；即使结果稳定，也可能存在系统性偏差。

## 5. 稳定预览和锚点

继续使用原有约 0.4 秒、最少 6 个样本、位置波动 2.5 厘米、法线波动 5°的稳定窗口。

平面来源按平面 ID 判断连续性；DepthPoint 的 ID 不要求跨帧稳定，纯深度来源采用独立稳定键，并依靠位置、法线、时间及空间跳变检查连续性。命中来源变化也会重置窗口，避免直接沿用另一来源的绿色状态。

确认时重新查询候选，并重新检查来源和稳定性。有平面时优先附着平面锚点；纯深度命中直接尝试 TryAddAnchorAsync，完全不要求 ARPlane 存在。异步完成后仍检查会话、深度新鲜度或平面跟踪状态，不接受失效结果。

确认成功后显示橙色立方体。提交坐标仍取锚点的表面原点，Go/React 数据字段和接口不变。

## 6. 代码位置

- Assets/Scripts/DepthAvailability.cs：深度能力、实际数据与新鲜度。
- Assets/Scripts/SurfaceHitPolicy.cs：来源选择、有效性、一致性及纯深度稳定键；包含可单独验证的 DepthFrameFreshness。
- Assets/Scripts/ARPlacement.cs：两次射线查询、来源提示、稳定预览与两类锚点创建。
- Assets/Scripts/InspectionBootstrap.cs：相机深度组件初始化。
- Assets/Editor/InspectionDepthChecks.cs：24 项确定性检查。
- Assets/Editor/InspectionProjectSetup.cs：Depth Optional 配置、测试及构建入口。

## 8. 仍然存在的限制

支持 ARCore 不等于支持 Depth；不支持深度的其他手机尚未实测，回退分支目前由确定性检查覆盖。无纹理、反光、透明、快速运动或完全遮挡的区域仍可能无可靠结果。深度模式也会增加设备处理开销，本次未量化帧率、温度或精度改善。

不会把平面外推当作检测，也不承诺隐藏墙面的重建、完整绿色边界或跨会话定位。应继续在同一场景比较实际误放、拒绝放置和落点误差。
