# 复杂环境标注优化方案

日期：2026-10-27。针对已实现稳定预览和 Anchor 的 1.2.1。该文记录提出方案时的分析。后续 1.3 已实现独立深度落点和一致性检查，见深度落点标注实现说明；多视角点云拟合没有实施。

## 1. 当前问题的边界

当前稳定窗口检查时间、位置和法线的一致性，Anchor 改善已放置内容的空间稳定性。稳定的错误平面仍可能通过这些检查；调长等待时间或加大平滑不会提供新的几何信息。

需要分别评估：误选其他平面、平面覆盖范围不符合物体轮廓、局部表面无法形成平面，以及跟踪质量不足。不能用单一阈值同时保证减少误判和提高识别覆盖率。

## 2. 优先方案：目标筛选 + 可选深度验证

### 目标筛选

- 增加自动/水平/墙面选择，按平面对齐类型筛选，减少前景桌面与背景墙面之间的误选。
- 水平类型本身不能可靠区分桌面与地面，不能仅用法线就声称完成语义识别。
- 结合拍摄距离、视线与平面夹角、平面持续跟踪情况筛选候选，参数需用本机现场样本调节。
- 平面面积只能作为辅助，不能把“面积更大”当作精度更高；过度过滤小平面也可能让小设备更难标注。

这些都属于本项目启发式规则，不是 SDK 提供的平面置信度。

### 深度验证

官方支持以 TrackableType.Depth 进行命中，并提供 PlaneWithinPolygon 作为回退。深度命中可用于局部或非平面表面，无需先成功识别出整张桌面或整面墙。[Google：Unity Raycast](https://developers.google.com/ar/develop/unity-arf/hit-test/developer-guide)

建议流程：

1. 运行时探测深度能力，并确认当前会话已经有有效数据；支持 ARCore 不等于支持 Depth。
2. 在同一个屏幕目标分别获得平面和深度命中。
3. 两者一致时，按选定策略使用可靠候选，再执行既有稳定窗口与 Anchor 流程。
4. 两者明显冲突时，提示存在遮挡或几何不一致，暂不确认；不能直接把不一致结果平均成看似稳定的位置。
5. 没有平面但存在可靠且稳定的深度命中时，允许局部表面标注，使用自由 Anchor。
6. 设备不支持或当前深度不可用时，明确显示回退到平面；不能将其标为已经通过深度验证。

接入通过 AR Camera 的 AROcclusionManager 进行。具体小米 14 型号和当前会话的能力仍应在应用内检测，不能根据机型名称或已安装服务推断。[Google：Unity Depth 接入](https://developers.google.com/ar/develop/unity-arf/depth/developer-guide)

## 3. 实现时的关键注意点

- 先使用 SDK 的 Depth Raycast，不优先自写稠密重建或复杂点云算法。
- 若比较两个 Raycast 返回的位置，可在同一 Unity 世界坐标下比较；如果进一步读取深度图，必须处理屏幕到深度图坐标的映射。
- 深度图的数值表示相机坐标的 Z 分量，不是射线长度，不能直接与 hit.distance 比较。[Google：深度数值定义](https://developers.google.com/ar/develop/unity-arf/depth/developer-guide)
- 如使用 Raw Depth，则在可用时结合置信度和局部邻域统计，剔除无效点与边缘混合；完整平滑深度图不提供同样的逐像素置信度图。
- Raw Depth 在无纹理区域也可能没有可靠估计，不能承诺白墙或玻璃都能处理。[Google：Raw Depth](https://developers.google.com/ar/develop/unity-arf/depth/raw-depth)
- 深度候选不一定有可跨帧复用的平面 ID，需要调整当前“同一平面 ID”的稳定窗口条件，按命中来源和空间连续性建立对应检查。
- 新来源不改变坐标单位和后端基本字段；只有成功确认、成功创建锚点后才能上报真实三维位置。

## 4. 固定巡检点的替代方案

如果现场允许布置标识，可在固定设备或墙面安装已知尺寸、特征丰富的参考图像，利用 ARTrackedImageManager 建立空间参考。识别到图像后，在该参考坐标系下标注，不必依赖空白墙面自然特征。ARCore 提供平面图像检测与跟踪能力。[Google：Augmented Images](https://developers.google.com/ar/develop/augmented-images)

该方案需要已知图像、尺寸和正确的现场安装关系；它不会自动获得整面墙的真实轮廓。适合固定资产巡检，不适合所有临时隐患场景。

## 5. 当前不优先的方向

- 仅增加更强平滑：可能让错误结果更稳定，无法修复系统性偏差。
- 仅用图像分割圈出墙面：二维区域本身不提供可靠的三维距离和坐标。
- Instant Placement 作为精度修复：其初始深度是估计值，后续几何更新可能改变位置与尺度，不适合作为精度保证。[Google：命中类型与取舍](https://developers.google.com/ar/develop/unity-arf/hit-test/developer-guide)
- 全场景稠密重建、自写 SLAM 或独立大模型服务：工程和验证成本较高，超出当前最小原型的优先范围。

## 6. 下一轮最小实施与验收

先增加深度能力诊断、目标类型选择和候选来源提示，再实现可选深度命中与平面交叉检查。保留当前稳定窗口和锚点，保留原来的水平面必做路径。

使用同一手机和相同场景比较 1.2.1 与新方案：有纹理平面、纯色墙面、遮挡桌面、多平面交界和小设备表面。记录误放、无法放置、首次可用时间和物理参照下的位置偏差，同时观察帧率与温度。降低误判不能仅以更高拒绝率作为成功证据。

当目标没有可靠三维结果时，明确提示继续扫描、改变角度或改选参考位置，不虚构精确坐标。照片标注如后续增加，应作为补充流程并单独建模，不能冒充本题要求的真实 AR 标注。


## 7. 用户纠正后的方案重点：漏检与覆盖不足

用户明确当前问题是遮挡情况下没有 ARPlane，或识别范围不完整。对此，目标类型选择只作为辅助，不能作为提高检出率的主要方案。现有 TryGetHit 强制 PlaneWithinPolygon 命中，平面不存在时后续稳定窗口没有输入。

应首先验证本机 Depth 能力和可见目标处的有效数据，并允许独立来源：有可靠 ARPlane 时使用平面；没有 ARPlane 但有可靠 Depth 命中时使用局部深度落点；两种结果都有时才交叉检查。不能要求两种同时存在，否则仍会阻断原本漏检的位置。

该方案增加的是可靠可标注位置，不自动补全 ARCore 的绿色平面边界。如果目标是扩大或重建墙面平面范围，则需要多视角深度/点云积累、离群点处理和 RANSAC 等鲁棒平面拟合，并维护自己的观测范围。拟合算法可参考 [PCL 官方平面分割说明](https://pointclouds.org/documentation/tutorials/planar_segmentation.html)，不意味着必须集成桌面 PCL 库到手机。

部分遮挡仍有可见墙面时可从可见区域获取数据；完全被遮挡且从未观察到的区域无法可靠恢复真实几何。对隐藏区域的平面外推必须标为估计，不能作为已检测边界或可靠落点。原生平面与 Depth 都缺失时，应引导移动到可观测视角，必要时使用已知参考标识。
